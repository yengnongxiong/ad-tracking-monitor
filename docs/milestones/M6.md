## A bug I caught before it shipped

I first set `TRUST_PROXY_HEADERS=true` for the API in docker-compose, assuming Next.js's rewrite proxy appends the client IP to `X-Forwarded-For`. A live check showed the API still saw the web container's IP. Reading the Next.js 16.3 source confirmed that external rewrites are proxied without adding the header, and a client-supplied one passes straight through. Trusting it would have let an attacker send a new fake IP per login attempt and bypass the rate limit entirely. Fixed by keeping the safe default; documented in ADR-003 and ADR-014; regression test added. Behind the dev proxy the login limit is effectively per email, which still stops password guessing.

## Design decisions to be ready to explain

1. **Sessions in Postgres, hashed (ADR-014).** Revocable (logout deletes the row), and a DB leak doesn't leak sessions. The trade-off versus JWTs is one indexed lookup per request.
2. **CSRF = SameSite=Lax + a custom header.** A cross-site page can make a browser send our cookie with a form POST, but it can't add `X-Requested-With` without a CORS preflight, which we never approve.
3. **Login rate limit in the database, keyed by email+IP.** It survives restarts and works with several API instances. The proxy-header finding above is a great "trust boundaries" interview story.
4. **Tenant isolation by construction.** Every query joins through `sites.user_id`. A wrong owner gets 404 (not 403), so ids can't be probed. One test walks every endpoint as the wrong user.
5. **Keyset pagination for run history.** `(started_at, id) < (cursor)` with an index on exactly that: stable pages while new runs arrive, and page 50 costs the same as page 1.

## Other changes

- **Migration 0003:** `login_attempts` (+ index), `sites.last_check_requested_at` (check-now cooldown), `jobs_finished_at_idx` (ops stats, retention), and the view now exposes `code`.
- `python -m tagmonitor.admin make-admin <email>`: admin rights are granted from a shell, never through the API.
- "Check now" moves an already-queued job to the front instead of queueing a second one, and joins a running one.
- The test container now mounts `pyproject.toml`, so lint and test config changes don't need an image rebuild.
