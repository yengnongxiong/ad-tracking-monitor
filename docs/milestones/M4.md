## Design decisions to be ready to explain

1. **The queue is Postgres (ADR-010).** `FOR UPDATE SKIP LOCKED` is the trick: claimers skip rows others hold, so there are no duplicates and no waiting. The interview follow-up is "what about scale?" Our jobs take seconds of browser time each, so Postgres throughput isn't the limit. The payoff is enqueuing jobs *in the same transaction* as the data that caused them (the M5 outbox).
2. **Leases with fencing tokens.** A lease is `(id, locked_by, attempts)`, and every write checks all three. Classic scenario: a worker freezes (a GC pause or a network partition), the reaper gives its job to someone else, then the first worker wakes up and tries to finish. Its write matches zero rows, it gets `LostLease`, and its results roll back. Tested.
3. **Website failures are data, not job failures (ADR-006).** A down site must produce an alert, so it can't just be retried until dead. Retries are for *our* failures only.
4. **Advisory locks (ADR-011).** Transaction-scoped for the scheduler and reaper (auto-released, so no stale leader), session-scoped for per-domain politeness (held for the capture, released even if the worker dies). Politeness waits don't use attempts.
5. **Graceful shutdown.** SIGTERM stops claiming, gives in-flight jobs 75 s, then cancels them; cancelled jobs put themselves back with the attempt refunded. Docker's `stop_grace_period` is 90 s so the worker gets to finish first.

## Other changes

- **Pool is autocommit** (`db/pool.py`): a connection held for a 2-minute capture (the domain lock) never sits "idle in transaction". Atomic work uses explicit `conn.transaction()` blocks.
- **Migration 0002** adds `check_results.code` (the machine-readable outcome from M3).
- **Browser relaunch is safe under concurrency:** with several captures sharing one Chromium, the browser being replaced is "retired" and closed only after its last capture finishes.
- **New dependencies:** `boto3` (in the PRD), and `boto3-stubs[s3]` as a **dev-only** type-stub package so mypy --strict can check the S3 calls. That's one addition beyond the PRD list, typing only, nothing at runtime.
- CI starts MinIO with `docker run` (GitHub service containers can't pass MinIO its `server /data` argument).
