## What's built

- **Check** (`checks/message_match.py`): a pure mapping from the verdict to a status (overall ≤ 2 fail, 3 warn, ≥ 4 pass). "No API key" is info, and API errors, the daily limit or invalid output are "error" (never alerts). It runs on mobile only, for sites with ad copy.
- **Model call** (`llm/`):
  - the forced tool call, with the Pydantic schema as `input_schema`
  - one retry on invalid output, feeding the validation error back
  - the cache (`llm_cache`, keyed on model, prompt version and hash, ad, and page text)
  - usage logging and a race-free daily budget (`llm_usage` plus an advisory lock)
  - SDK retries on 429 and 5xx, a timeout, and bounded `max_tokens`
- **Prompt** `evals/message_match/prompts/v1.md`: a rubric for the three sub-scores and the overall score. Page and ad text are HTML-escaped inside `<ad>`/`<page>` tags so page content can't break out and issue instructions. This version is my first draft for you to improve on the dev split.
- **Worker:** the call happens after the per-domain lock is released. A failed call never costs the other checks.
- **Web:** the site page shows the sub-scores, what doesn't match, suggestions, and which model and prompt produced them. The ad copy form says an AI model reads the page text.
- **Alerts:** a failing match emails "Your landing page doesn't match your ad" (after the usual confirmation re-check, which is a cache hit).
- **Eval CLIs** (`evals/`):
  - labels are blind, resumable, and fingerprinted to the exact ad and page text they were given for
  - the split is by page and stable as examples are added
  - `run` enforces "test once"
  - `report` writes Wilson intervals, QWK with a seeded bootstrap interval, MAE, bias, the confusion matrix, disagreements and cost

Design: [ADR-017](../decisions.md#adr-017-the-model-call-happens-outside-the-check-the-check-maps-a-verdict-to-a-status-m9).

## Evidence

**Tests.** `tests/test_message_match.py` and `tests/test_evals.py` cover:

- the status mapping
- prompt rendering, including the tag-escape test
- the request shape
- cache hits and misses (including an edited prompt file)
- the one retry with its error feedback
- giving up after two invalid answers
- API errors
- the daily limit, including 10 concurrent callers against a limit of 3 (exactly 3 calls go through)
- the real Anthropic SDK against a mock HTTP handler: it checks that `temperature` lands in the JSON body and that tool use is parsed
- three capture-job scenarios on the fixture server: ad copy, no ad copy, and a failing model
- kappa matching scikit-learn on 25 random datasets (to 1e-12)
- the unused-category subtlety
- the dataset formats, stale labels, split stability, and the interactive label session (driven through the CLI with scripted input, in a temp folder)
- `collect` on the fixture server
- `run` and the report, including cache reuse and the test-split rule

Full suite: **540 passed** (`docker compose run --rm tests pytest -q`); ruff, ruff format and mypy clean; web `npm run lint`, `npm run typecheck` and `npm run build` clean.
