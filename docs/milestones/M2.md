## Deviations from the PRD (please read)

1. **The SSRF guard lives in an egress proxy, not only in `context.route`** (ADR-004). I tested the PRD's approach first: Playwright's route handler never sees redirect hops, so a public URL redirecting to `127.0.0.1` would get through. Every capture now runs through a per-capture proxy that validates and IP-pins every connection. This is stronger than the PRD asked for: it also covers WebSockets and CORS preflights, and it closes DNS rebinding for browser traffic.
2. **Horizontal overflow compares `scrollWidth` with the device's viewport width, not `innerWidth`.** On an emulated phone, Chrome widens the layout viewport to fit wide content, so `innerWidth` came back as 1208 on a 412-px phone and `scrollWidth > innerWidth` could never be true. The capture records both numbers plus `viewport_width`. The test asserts the `innerWidth` behavior, so a future Chrome change is caught.
3. **"Network quiet" counts finished requests as activity, not just started ones.** With "no new request for 2 s", a 5-second image started at 0 s let the wait end the moment it arrived, before Chrome recorded its paint, so LCP was read too early. It depended on timing and showed up as an order-dependent test failure. Counting finishes fixed it: the slow-LCP fixture now reads 5.03–5.04 s every time, across 8 back-to-back captures.
4. **`PageCapture.dom.viewport_width` and `blocked`** are additions to the §9 record list (the SSRF proxy's refusals are useful evidence in the UI and for debugging).

## Design decisions to be ready to explain

1. **Why an egress proxy (ADR-004).** "Show me how you'd stop SSRF in a headless browser" is a great interview question. The story: the obvious hook, request interception, doesn't see redirects (demonstrated with a 20-line experiment), so enforcement moved to the connection layer, the same idea as Stripe's Smokescreen. The proxy connects to the IP it validated, which also kills DNS rebinding. What's left, and the defense-in-depth advice, is written down.
2. **Capture once, analyze many (ADR-005).** Browser I/O is slow and flaky; logic shouldn't be. One serializable `PageCapture` per page load means checks are pure functions tested in milliseconds, and old captures can be re-analyzed when tracking endpoints change.
3. **Website failures are data; capture failures are exceptions.** A DNS failure, timeout, 500 or blocked redirect comes back inside the `PageCapture` (`navigation.error_code`), so checks can report it. Only failures of *our* machinery raise `CaptureError(transient=True)`: browser crash, 60 s hard budget exceeded, renderer crash. This is what lets M4 retry only what's worth retrying (ADR-006, coming in M4).
4. **Tracking stubs instead of mocks.** The fixture pages use the real Meta and Google snippets and URLs. Playwright answers those hosts locally with stand-in scripts that produce the same network traffic (`/tr?id=…&ev=PageView`, `/g/collect?tid=…&en=page_view`, …). The checks see exactly what they'd see in production, and nothing leaves the machine. Fun detail: the Meta stub needed a timestamp per hit because Chrome's image cache otherwise merges two identical beacons, and real `fbevents.js` does the same thing.
5. **Test isolation by construction.** The test resolver knows exactly one hostname (`fixtures.test` → 127.0.0.1), and that's the only allowlisted host. Any accidental real-world request fails DNS inside our own proxy, including Chromium's own background traffic (visible as `dns_failure` for `www.google.com`).
