## Design decisions to be ready to explain

1. **Same-origin proxy (ADR-003).** The browser only talks to Next.js, which forwards `/api/*` to FastAPI. *Why:* the session cookie stays first-party, so `SameSite=Lax` and httpOnly just work with no CORS. *Alternative:* CORS with credentials across two origins, which is harder to secure and increasingly blocked by browsers.
2. **One image, two commands (ADR-002).** API and worker share the Playwright-based image. *Why:* one dependency install and no version drift between them. *Cost:* a bigger API image.
3. **Health means "can query the DB."** `/api/health` runs `SELECT 1` and returns 503 otherwise. A process that's up but can't reach its database isn't healthy. Docker Compose uses this to start the web tier only once the API really works.
4. **Everything runs through Docker (`make test`, `make lint`).** The only host requirements are Docker and make, so "works on my machine" problems shrink. The host-side `uv run pytest` path still works for fast iteration.
5. **Non-clashing host ports (5433/8001/3001).** This stack can run alongside abtest-platform.
